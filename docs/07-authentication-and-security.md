# 認証・セキュリティ

## 基本方針

Firebase Authentication をログイン認証に利用します。

認証主体は `Account` とし、予約者情報とは分離します。

- Accountはログイン可能な利用者だけを保持します。
- 管理者代理予約・非会員予約ではAccountを作成しません。
- 予約者の氏名・メール・電話等はReservationのスナップショットです。
- メールアドレス一致だけでAccountと既存予約を紐付けません。
- 過去の管理者登録予約を後からAccountへ連携しません。
- マイページには `Reservation.account.firebaseUid == session.uid` の予約だけを表示します。

## 本人予約

ログイン済み利用者が予約する場合のみ、Firebase UIDからAccountを取得してReservation.accountへ設定します。

Accountが存在しない場合は、予約作成処理で曖昧なメール照合を行わず、Account登録フローを完了させてから予約します。

## 管理者代理予約

管理者が入力した予約者情報はReservationへ直接保存します。

- Account検索を行わない
- Accountを自動作成しない
- 既存Accountとメールが一致しても紐付けない

これにより、本人が登録していないのに会員情報が存在するように見える状態を避けます。

## 過去予約

Account作成時に過去予約の探索・自動紐付け・手動紐付けを行いません。

過去予約の問い合わせや変更は、予約番号と連絡先等の既存の本人確認フローで扱います。
