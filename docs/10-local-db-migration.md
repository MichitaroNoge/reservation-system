# 開発DB移行の実装・検証記録

対象はローカル開発のみ。Cloud SQL、検証・本番環境、Vercel環境変数は変更していません。
Data Connectの既存定義・生成SDK・Repositoryは保持し、DB_PROVIDER未指定の既存デプロイは従来実装を選択します。

## 実装

- PostgreSQL 17.11のDocker Compose、ループバック限定ポート、名前付きVolume、ヘルスチェック。
- GraphQLの17テーブル・4 EnumをDrizzleへ翻訳し、SQLマイグレーションを生成。
- Repositoryの47メソッドをDrizzleで実装。APIの予約コードと内部UUIDを分離し、既存DTOへ変換。
- Accountと予約者スナップショットの分離、論理削除、明細価格、終了時刻、確認連絡のリセットを維持。
- 予約作成・明細更新・店舗割り当て・変更承認はトランザクション。採番と関連更新にはトランザクション単位のアドバイザリロック。
- 初回本人予約のAccount作成と予約作成を一括更新。Account作成/削除の確認処理も同じUIDのロックを使用。
- 本人予約はSQLでAccountを限定。Firebaseトークン検証、管理者claims、公開マスター読み取り、追加連絡先トークン、cron認可を維持。
- 無効な管理者IDトークンは401へ変換。DB例外のSQLパラメーターはAPIに露出させない。
- UTC TimestampをISO文字列へ変換し、日付・利用時刻の形式を維持。
- 固定UUID/自然キーを使った冪等Seed。SeedはAuthユーザーを変更せず、Resendへ送信しない。
- 開発専用ツールは環境、ループバック、専用DB名、URLの接続先上書きパラメーターを検証。初期化と実PostgreSQLテストは確認引数が必須。
- DB関連設定だけをNext.jsへ明示的に渡し、既存Auth/Resend設定の.env.local優先順位を維持。
