既存の未コミット変更を保持し、ローカルの現行実装をレビューしました。デプロイは行っていません。

## 最も影響が大きかった原因

認証済みの更新APIが、DBの種類にかかわらずFirestoreを回数制限の保存先にしていました。現在のFirebase接続先への読み取り確認は `5 NOT_FOUND` を返しました。この構成では、FirebaseへのログインやDBの読み取りが成功しても、プロフィール登録・予約・管理操作の更新は回数制限の検証で503になります。

`DB_PROVIDER=drizzle` の場合はPostgreSQLに回数制限を保存するよう修正しました。制限を無効にしたり、メモリへフォールバックしたりせず、トランザクションとロックで複数プロセスからの同時実行にも対応しています。開発DBには追加テーブルだけを作るマイグレーションを適用済みです。

## 朝の確認手順

1. Docker Desktopを起動し、プロジェクトで `npm run db:up` → `npm run db:migrate` → `npm run dev:local` を実行します。今回の開発DBへのマイグレーションは適用済みですが、再実行しても安全です。
2. 顧客画面を再読み込みし、登録済みユーザーでログインします。プロフィール未保存のユーザーは「アカウント情報」を保存してください。認証ユーザーの再登録・削除は不要です。
3. 顧客管理で該当アカウントの表示を確認し、氏名・電話を編集します。過去予約の氏名・メールは変わらないことを確認します。
4. 仮予約／本予約を申請し、本人の予約一覧に表示されることを確認します。
5. 管理画面で承認・店舗割当・確認連絡を行い、読み込み直しても状態が保持されることを確認します。
6. 人数や日時を変更し、古い割当と確認連絡がクリアされ、必要に応じて「本予約確定」に戻ることを確認します。
7. メールテンプレート管理でメール変更通知・追加連絡先確認もプレビューできることを確認します。

現在のローカルメール環境はテスト宛先へのリダイレクトが設定されています。予約関係の実メール受信はその宛先で確認してください。Firebaseの確認メール・パスワード再設定メールは別系統です。
