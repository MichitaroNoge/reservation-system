## クラウド反映が保留になった理由

Cloud SQLのオンデマンドバックアップ作成APIがHTTP 400で拒否された。

> Invalid request: Operation is not allowed for Cloud SQL No Cost Trial for Firebase Data Connect.

無料トライアルのままバックアップを省略して追加専用マイグレーションを適用する操作も、自動承認レビューに拒否された。拒否理由は「バックアップ取得後という前提を省略した既存Cloud SQLへの実スキーマ変更」である。拒否された操作を別の手段で実行していない。追加専用例外はツールから除去し、成功バックアップ必須の保護を維持した。

そのため、クラウドDB・IAM権限・ネットワーク設定は未変更。新しい有料インスタンスや秘密鍵も作成していない。バックアップなしでの3テーブル追加とアプリ接続権限付与を明示的に承認してもらうか、バックアップ可能な構成を先に準備する必要がある。通常構成への移行は料金が発生し得るため、承認なく変更しない。

参照: [Firebaseの無料トライアル制限・直接SQL接続](https://firebase.google.com/docs/sql-connect/manage-services-and-databases)、[Cloud SQL IAMユーザー](https://docs.cloud.google.com/sql/docs/postgres/add-manage-iam-users)、[Cloud SQL Connector](https://docs.cloud.google.com/sql/docs/postgres/connect-connectors)。

## 登録フォームの入力消失修正（2026-10-15・後続報告）

- 報告: メールアドレス・パスワードを入力後、電話番号を入力すると認証入力が空になる。
- 原因: React Hook Formのreactive valuesは親画面の状態を参照するが、認証入力は送信時にしか親へ反映していなかった。氏名・電話・住所等の変更で親のプロフィール状態が更新されると、古い空の認証入力でフォームがリセットされた。
- 修正: ログイン・登録それぞれのメールアドレスとパスワードを、既存のReact stateへ入力時に同期。認証成功・ユーザー切替時の既存クリア処理を維持し、永続保存は追加しない。
- 併せて、ログイン/登録タブの切替で入力済みメールを予約フォームの空メールへ上書きしていた箇所を修正した。
- 最終コードを一時的なlocalhostの3001番サーバーで検証。1440×900でメール・パスワード→名前→電話番号の逐次入力→住所→ログイン/登録タブ切替、390×844で旅行会社区分変更・担当者入力・電話番号の必須エラー時にも、メール・パスワードが空欄にならないことを確認。
- ブラウザー検証は架空の入力のみ。電話番号を空欄にした送信はフロントエンド検証で停止し、実アカウント登録・Firebaseログイン・メール送信は行っていない。ブラウザーの実プロフィール自動入力は未検証。
- npm testは107件成功。最終npm run build成功（既存警告5件）。git diff --check成功（改行変換の注意のみ）。
- 検証タブを閉じ、表示幅を戻し、一時サーバーを停止。既存3000番サーバーとクラウドDBは変更していない。
