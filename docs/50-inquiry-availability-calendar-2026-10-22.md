# 空き状況の問い合わせから予約カレンダーを確認（2026-10-22）

## 対応内容

- 管理者の問い合わせ詳細で、空き状況問い合わせの食事日時・人数・質問の下に「予約状況を確認」ボタンを追加した。
- ボタンを押すと中央の大きな子画面で当日の時間軸カレンダーを表示する。初期日は問い合わせの食事日。希望開始時間へスクロールし、緑の点線で目印を表示する。
- 上部に問い合わせの食事日時・人数を表示する。終了時間は未指定のため、管理者が予約状況を確認して受入可否を判断する方式とした。問い合わせ人数は既存予約人数に加算しない。
- 本予約・仮予約・承認待ちを色と文字で区別し、重なる予約は横に並べる。予約者・時間帯・人数・予約番号を表示する。店舗未割当も対象で、キャンセル済み・却下済みは除外する。キャンセル申請中は従来の集計区分を維持する。
- マスタの合計上限、既存予約の最大同時利用人数、本予約・仮予約込みの上限超過警告を表示する。承認待ちは別の区分で表示し、予約済み人数には含めない。
- マスタの受入不可期間を赤い時間帯と説明で表示する。利用時間が不明な予約は「時間要確認」とし、空きがあると断定しない。
- 前日・翌日、日付選択、希望日への復帰、手動の再読み込みに対応する。日付は日本時間として扱う。取得日が変わると古いリクエストを中断し、別の日の応答を混在させない。
- 子画面を開いた時に最新情報を取得。表示中は60秒ごととフォーカス復帰時に再取得する。取得失敗時はエラー・再読み込みを表示し、同日の過去の取得内容を表示する場合は最新ではないことを明示する。
- 回答画面はマウントしたまま保持し、本文・件名・テンプレート選択などの入力内容を維持する。「閉じて回答に戻る」やEscapeでカレンダーだけを閉じ、開いたボタンへフォーカスを戻す。

## 実装・影響範囲

既存の管理者用`GET /api/admin/calendar`と公開メニュー取得、`calendarDay`／`calendarLanes`／`calendarCapacityWarning`を再利用した。既存の認可・no-store・日またぎ取得・予約区分の判定を使用する。新規API、DB変更、依存ライブラリ追加、予約データの変更はない。閲覧では問い合わせ・予約の作成や承認、席の確保、メール送信を行わない。

- `components/inquiries/inquiry-availability-calendar.tsx`：問い合わせ用の日別カレンダー子画面。
- `components/inquiries/inquiry-management.tsx`：空き状況問い合わせの詳細へ組み込み。
- `components/inquiries/shared.tsx`、`inquiry-conversation.tsx`：問い合わせ原文の下に管理者向け操作を置く任意の表示枠を追加。お客様向け表示は変更しない。
- `components/ui/dialog.tsx`：RadixのDialogTriggerを共有部品として公開し、子画面を閉じた時のフォーカス復帰に利用。
- `tests/reservation-calendar.test.ts`：問い合わせ時の集計区分・除外対象・受入不可期間を確認。
- `tests/db/performance.test.ts`：日別の実DB取得、日またぎ、管理者認可、予約・送信ジョブを変更しないこと、再取得時の最新情報を確認。

## 制約

構造化された希望日時・人数が保存されている空き状況問い合わせにボタンを表示する。過去の自由記述だけの問い合わせは従来どおり本文から確認する。終了時間・滞在時間がないため、問い合わせに対する自動の空き判定や予約枠確保は行わない。メニューなどから既存予約の利用時間を確定できない場合は、従来のカレンダーと同様に保守的な時間帯表示と「時間要確認」の案内を使用する。

最終ビルド成功。npm run start:localでlocalhost:3000へ反映済み。起動後のHTTP 200とカレンダーAPIの未認証401を確認した。
