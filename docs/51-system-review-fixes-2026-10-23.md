## 対応内容

| No. | 優先度 | 問題と修正 |
| --- | --- | --- |
| 1 | P1 | 古い編集フォームから新しい人数等を上書きできる。管理者の予約更新APIで expectedRevision を必須とし、予約トランザクション内で現在の revision と照合。不一致は409。フォームを開いた時点の版を送信し、失敗後も入力内容とエラーを画面に保持する。 |
| 2 | P1 | 再送待ちの受付メールをキューが処理済みにしてしまう。待機中は RateLimitError と次回待機秒数を返し、既存キューの制限待ち処理を使用する。試行回数を消費せず待機日時を引き継ぐ。送信上限に達した未送信メールも成功扱いにしない。 |
| 3 | P2 | 人数だけの変更承認で、管理者指定の終了時刻がメニューの標準時間に置き換わる。開始時刻とメニューの組合せが同じ場合は登録済み終了時刻を保持する。受入不可期間との照合と実際の保存に同じ終了時刻を使用する。開始時刻またはメニューが変わる場合は従来どおり再計算する。 |
| 4 | P2 | 確認メール再試行でクリック日時ごとに別の送信キーが作られ、結果不明の送信を重複させる。予約に confirmation_email_generation を追加し、同じ送信では本文・宛先・キーを再利用する。確認連絡済みを明示的に未実施へ戻した場合だけ世代を進める。旧 manual/日時 形式の記録も引き継ぐ。23時間を超えた結果不明の送信は停止し、送信履歴の確認手順を案内。送信待ちは20秒で打ち切り、送信処理と確定を予約単位で直列化する。 |
| 5 | P2 | 非同期メール配送の完了後も、問い合わせ詳細が送信待ちのままになる。未完了配送がある間は10秒ごとに状態を取得し、画面に戻った時と手動更新でも再取得する。入力中の回答文はリセットしない。古い取得結果が新しい操作結果を上書きしないようにする。 |
| 6 | P2 | 匿名のお客様への未送信回答が要対応件数から除外される。履歴を利用できない匿名のお客様は、送信成功または管理者による明示的な結果確認まで要対応に残す。回答済みの匿名問い合わせに追加回答を作成した場合も対応中に戻して配送完了まで件数に残す。ログイン済み利用者は従来どおり公開履歴で回答を確認できる。 |
| 7 | P2 | 匿名問い合わせフォームを30分以上開くと送信できない。送信識別子を維持して送信証明を更新し、期限切れ403では一度再準備して再送する。入力内容と応答不明時の送信識別子を保持し、重複受付を防ぐ。証明の有効期間30分・最低2秒・同一オリジン・ブラウザーとの結び付けを維持。識別Cookieは24時間にし、25分での証明更新、再表示時の準備、初期準備失敗時の入力を保持した再準備に対応する。 |
