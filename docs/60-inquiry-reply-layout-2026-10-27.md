# 問い合わせ回答画面の情報整理

実施日: 2026-10-27

## 2026-11-09追加仕様（採用）

「回答済」とメールの送信完了の違いを明確にするため、最新の依頼に基づき以下を採用。下記の2026-10-27の記録より、この追加仕様を優先する。

- 回答保存後は「回答を保存しました。」と表示し、空になった回答フォームを保存済み回答の確認表示に切り替える。再び開いた場合も回答があり下書きがなければ確認表示とする。
- 確認表示には宛先、回答日時・件名・本文、独立した「通知メール」の状態を表示する。新規回答を制限する未解決のメールが複数あればすべて表示し、すべて解決済みなら最新の回答を表示する。
- 通常の「送信待ち」「送信中」は注意色の警告にせず、自動で更新される旨と「メールの送信完了後に、追加の回答を作成できます。」を表示する。
- 「送信失敗」「結果の確認が必要」は、回答が保存されていることと必要な操作を明示し、その回答から「同じメールを再試行」「送信結果を確認」へ進める。
- 確認表示から「送信状況を更新」「回答履歴を見る」を利用できる。回答履歴内の対象メールの復旧操作も維持し、待ち状態が長く変わらない場合にも復旧できる。
- すべての回答メールが送信済み、または管理者による確認・終了済みになったら、下部の「追加の回答を作成」から入力画面へ切り替える。無効な空のフォームや送信ボタンを表示し続けない。
- 入力中に他の処理で未解決の回答が追加された場合も下書きを保持する。送信結果の記録は確認チェックを必須とし、記録失敗時は確認画面でエラーを表示して再操作できるようにする。
- 回答済の自動判定、会員／匿名の扱い、10秒間隔の画面更新、API・DB・メールキュー・重複防止・再送期限／回数制限は変更しない。管理画面の変更に限り、お客様の履歴画面は変更しない。

実装・検証結果: [79. 問い合わせ回答後の結果表示](79-inquiry-reply-result-2026-11-09.md)。

## 変更

- 主画面を「問い合わせへの回答」とし、問い合わせ番号・状態を1行にまとめた。
- 問い合わせ本文、空き状況の確認ボタン、宛先、回答件名、回答本文を表示。氏名とメールアドレスは宛先行に1回だけ表示する。問い合わせ日時・管理情報や過去の回答を回答フォームの上へ重ねて表示しない。
- 長い問い合わせ本文は本文内でスクロールして確認できる。
- 空き状況の食事日・開始時間・人数を3列にまとめ、自由記入の質問はその下に表示。質問がない場合は不要な案内を追加しない。
- 「受付情報」の子画面へ、受付日時・種別・関連予約番号／予約詳細への移動・受付メールの状態／再試行を移動。
- 「回答履歴」の子画面へ、過去の回答・回答者・回答日時・回答メールの状態を移動。再試行・送信結果の確認と記録は、対象の回答と同じ位置に表示する。
- 送信未完了の回答がある場合は、新しい回答を送れない理由を主画面に短く示し、回答履歴から復旧できる。受付メールの失敗だけでは新規回答を制限しない。
- 入力中の「下書きを保持しています。画面の再読み込み・ログアウトで消えます。」「『送信する』を押すと回答が保存されます。ログイン済みのお客様は履歴画面でも確認できます。」を削除。
- 下書きの保持・閉じる際の選択・定型文の子画面／挿入位置・送信確認・権限・メール再試行の条件を維持。お客様側の問い合わせ履歴の表示は維持する。
- 「閉じる」「回答を確認」を画面下部に固定し、本文のスクロール位置に関係なく操作可能にした。補助操作の成功・エラーは子画面内だけで表示する。

## 実装

`components/inquiries/inquiry-management.tsx` の主画面を整理し、補助操作を `inquiry-admin-support.tsx` に分離。`inquiry-conversation.tsx` は回答だけを表示する指定と、回答ごとの操作欄に対応。既存利用時の表示は変更しない。API・DBの変更なし。
