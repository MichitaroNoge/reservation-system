# キャンセル申請画面の操作整理

実施日: 2026-10-28

同日追加更新: お客様向け共通仕様の採用により、操作欄は画面下端の共通部品へ移行し、「戻る」は戻り先を明示した「予約一覧へ戻る」へ変更。実際の戻り先も予約一覧とし、元の表示位置を保持する。以下は最初の単独画面改善の記録。現在の仕様・検証は[共通仕様](customer-screen-standard.md)と[共通化の記録](62-customer-screen-alignment-2026-10-28.md)を参照。

## 依頼と実装

- 「キャンセル対象の予約」の見出しとアクセシブルな領域名を「ご予約内容」に変更。
- 「上記の予約についてキャンセルを申請します。対象の予約に間違いがないかご確認ください。」と「ログイン中のアカウントに紐づく予約だけ申請できます。」をキャンセル申請画面から削除。
- 単独の戻るリンクと上部の重複する戻る操作を廃止し、「キャンセルを申請する」の左隣に共有Buttonの枠線付き「戻る」を配置。狭い画面では必要に応じて折り返し、送信中は戻る操作も無効にする。
- 共有の申請ボタン部品に任意の戻る操作を追加し、キャンセル申請だけで使用。変更申請の戻り先や操作は維持。
- 予約内容の表示・編集不可、戻り先、キャンセル料の案内、申請前の確認ダイアログ、送信時の本人確認・二重送信防止を維持。API・DB・キャンセルの業務ルールは変更しない。

主な変更: `app/reservations/customer-portal.tsx`、`app/reservations/components/customer-request-submit.tsx`。

## 検証

- `npm test`: 171件成功。
- `npm run build`: 成功。既知の`.next`生成権限の問題を避け必要な権限で実行。既存のHook依存警告2件あり。
- 架空の本人予約を使う隔離ブラウザー環境で、PC1280px・スマートフォン390pxを確認。どちらも戻るボタンと申請ボタンは同じ行に隣接し、ページの横はみ出しなし。390pxでは両ボタンの高さ44px。
- 見出し・領域名が「ご予約内容」になり、指定の説明文2つと重複した上部の戻る操作が表示されないことを確認。
- 画面の戻るボタンで従来の手続き選択へ戻ること、PC・スマートフォンでキャンセル料の案内と確認ダイアログが表示され、ダイアログの「戻る」で未申請のままフォームへ戻れることを確認。
- 証跡: `review-artifacts/cancellation-layout-2026-10-28/cancellation-desktop.jpg`、`cancellation-mobile.jpg`。

PGliteの一時DB・モック認証・架空データで確認し、実際のキャンセル申請や実メール送信は行っていない。検証用サーバー・タブを終了し、画面幅設定を解除した。既存のlocalhost:3000と配送ワーカーの起動状態は変更していない。ローカルソースと本番用ビルドに反映し、本番・クラウドへのデプロイは行っていない。
