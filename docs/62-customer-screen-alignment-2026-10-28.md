# お客様向け画面の共通仕様の適用

実施日: 2026-10-28。利用者が前ターンの仕様案を採用し、共通仕様への記載と既存画面の修正を依頼した。

## 共通仕様と実装

実装前に`customer-screen-standard.md`を作成して確定仕様を記録し、AGENTS.md・標準仕様・UI標準・ドキュメント一覧から参照した。新規のお客様向け画面もこの仕様に従う。

- `CustomerPageFrame`でフォーム・設定・詳細を720px、予約一覧・履歴を960pxに統一し、タイトルを1回だけ表示する。旧予約フォームの共通枠内の余白・見出しは、globals.cssの限定した互換ルールで調整した。
- `CustomerPageActions`で画面下端の操作欄を共通化。戻るは枠線付きで主要操作の左。収まらない幅では戻る・主要操作の順で折り返し、44px以上の高さを維持する。実際のフッター高をResizeObserverで計測して本文に余白を確保し、ダイアログは前面に表示する。
- 予約申請の各ステップ、予約一覧、本予約への変更・予約変更・キャンセル申請、完了画面、設定画面、お問い合わせ・送信完了、問い合わせ履歴・詳細、申請のログイン案内に適用。上部の重複した戻る操作と重複タイトルを取り除いた。
- 本予約への変更・予約変更・キャンセル申請は「予約一覧へ戻る」で元の一覧位置へ戻る。完了後は「お手続きトップへ戻る」。予約一覧から問い合わせに進む場合の表示位置も本人別のsessionStorageに保持する。
- 問い合わせ詳細からは「問い合わせ履歴へ戻る」で元のページと表示位置を復元。保存するのは本人別のページ番号・スクロール位置だけで、一覧データ・問い合わせ本文・認証トークンは保存しない。破損した保存値は既定値へ戻す。
- 予約申請の前後ステップ移動は入力を保持する。予約変更・本予約への変更・問い合わせ・設定で未保存入力を破棄する場合は確認を表示。プロフィール編集をやめる場合も破棄前に確認する。ブラウザーでの離脱警告と確認済みの戻る操作が二重に出ないようにした。
- 設定のプロフィール保存と問い合わせ送信は、共通操作欄から既存フォームのsubmitを呼ぶ。入力検証・保存・本人確認・予約の業務ルール・キャンセル料確認・メール配送処理は既存処理を維持した。

## 検証

- `npm test`: 最終コードで172件成功。保存位置の不正値・破損値のテストを追加。既存のホームメニュー検査が一般的なDialogの`onOpenChange`も旧メニューと誤認したため、その検査対象を本来のCustomerPortalHomeへ限定して再確認した。
- `npm run build`: 最終コードで成功。既知の`.next`生成権限の問題を避け必要な権限で実行。既存のHook依存警告2件あり。
- PC1280pxでフォーム枠720px、画面タイトル1つ、操作欄の下端900px＝画面高900px、両ボタンの高さ44px・同じ行を実測。
- スマートフォン390px、狭い320px、タブレット768pxで横はみ出しがないことを確認。320pxでは戻るが上・送信が下へ折り返し、フッター高133px・ボタン高44px。768pxではフォーム幅720px。
- 390pxのお問い合わせで、最後の入力欄がページ最下部では操作欄より上に表示できることを計算確認。本文の入力を残して「入力を続ける」で編集に戻れることと、共通欄の送信ボタンで既存の項目別エラーが表示されることを確認。
- 予約一覧からキャンセル申請へ進み、戻ると一覧のスクロール位置が復元されることを確認。変更理由の入力時と本予約への変更の同意時の破棄確認も確認。キャンセル料の確認から「入力に戻る」で未申請のまま戻れることを確認。
- 予約フォームの第1〜3ステップの移動、入力済みの実部品による第3〜4ステップ移動で日付・人数・備考の保持を確認。検証ブラウザーの日付・時間の自動入力の確定が安定しなかったため、後者は有効な架空データを初期値に持つ検証用ラッパーを使用した。製品の入力処理は変更していない。
- 設定の未保存氏名を保持して編集に戻れること、共通欄の保存ボタンから一時DBへプロフィールが保存されること、編集終了の破棄確認を確認。
- 問い合わせ履歴2ページ目から詳細へ進み、元の2ページ目と表示位置（302px）へ戻れることを確認。存在しない問い合わせの取得エラーでも戻る操作が有効なことを確認。

証跡は`review-artifacts/customer-layout-2026-10-28/`。`cancellation-desktop.jpg`、`cancellation-mobile.jpg`、`contact-mobile.jpg`、`booking-mobile.jpg`、`settings-mobile.jpg`を保存した。

検証はモック認証・架空ユーザー・一時PGlite DBのみ。実予約の申請・変更・キャンセル、実宛先へのメール送信、実際のGoogle認証・アカウント削除は行っていない。認証・予約・問い合わせのAPIやDBスキーマは変更していない。ローカルソースと本番用ビルドへ反映し、本番・クラウドへのデプロイは行っていない。

検証用のタブとサーバーは終了し、画面サイズ設定を解除した。既存のlocalhost:3000と配送ワーカーの起動状態は変更していない。
