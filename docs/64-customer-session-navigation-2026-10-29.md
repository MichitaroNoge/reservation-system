# 顧客画面のログイン状態を保持する画面遷移

実施日: 2026-10-29。問い合わせ・問い合わせ履歴からトップへ戻る際の認証確認表示と待ち時間の改善、および今後の新規画面向けの共通仕様化依頼。

## 原因と変更

予約操作はCustomerPortal内の状態切り替えでトップへ戻る一方、問い合わせの戻る操作はwindow.location.assignで文書全体を読み直していた。またuseCustomerSessionは画面のマウントごとに未判定状態から開始していた。このため、前回63で未ログイン画面のちらつきを防いだ後も、認証状態の復元中表示が残っていた。

- CustomerPageActionsの内部URLへの移動をNext.jsのrouter.pushへ変更。予約側のonBackによる既存の状態切り替えは維持。
- useCustomerSessionのユーザー・復元状態・永続化エラーを、ブラウザー内で共有する外部ストアへ移動。ReactのuseSyncExternalStoreで購読し、画面のマウントごとの初期化を廃止。Firebaseの監視は1回だけ開始し、利用画面がない間もログアウト／ユーザー変更を追跡する。サーバーレンダリングでは常に未判定の初期値を使用する。
- 認証操作のエラーは各画面内で保持。メール認証の再確認は共有状態へ反映し、同じFirebase Userオブジェクトの更新も再描画する。
- 履歴行からの詳細表示もrouter.pushへ変更。問い合わせ完了後の「別の問い合わせを送る」はフォームを初期化するか内部遷移し、文書の再読み込みを廃止。
- 未保存入力の破棄確認、送信中の無効化、同じ内容での再試行、本人の履歴取得、匿名問い合わせ、一覧ページ／表示位置保持を維持。DB・API・権限・メール配送の変更なし。

共通仕様はcustomer-screen-standard.mdの「ログイン後の画面遷移」に確定仕様として記載し、standard-specification.mdから参照する。初回・直接アクセス・再読み込みでの認証復元表示は維持し、通常の内部遷移と区別する。

## 検証

- npm test: 174件成功（追加2件）。画面の購読解除／再購読でログイン状態が維持され、監視が増えないこと、画面がない間のログアウト・別ユーザーへの変更、サーバー用初期値の分離、同じUserのメール認証状態更新、永続化エラーの保持を確認。
- npm run build: 成功。生成権限を付けて実行。既存のHook依存警告2件（admin-app.tsx、email-template-management.tsx）は残る。
- 実際のNext.js App Routerと実コンポーネントを使い、モックFirebase・架空データ・一時PGlite DBを組み合わせた隔離環境でPC1280px／スマートフォン390pxを確認。
- 初回の認証復元を明示的に保留し、確認中表示が出る一方、未ログイン用の入口を表示しないことを確認。認証復元後に記録をリセットし、お問い合わせ・履歴・詳細・トップを往復。文書識別子は同じまま、Firebase監視登録は1回、認証確認コメントと未ログイン画面の表示回数はともに0回。
- 履歴は2ページ目から行クリック／番号リンクで詳細を開き、戻ると2ページ目へ復帰。390pxではスクロール位置293pxへ復帰し、ページ全体の横はみ出しなし。
- 問い合わせの入力後に戻ると破棄確認を表示。「入力を続ける」で本文を保持し、「破棄して戻る」でトップに復帰。送信中は戻る・送信が無効になることを確認。
- 架空問い合わせを隔離DBに1件登録し、完了画面の「別の問い合わせを送る」で文書を再読み込みせず、空の本文・初期種別へ戻ることを確認。初回の検証用プロキシはAPI側URLとOriginが異なるため403となったが、検証側のURL情報を合わせて再確認。製品の同一オリジン確認は変更していない。
- 履歴表示中のモックログアウトで履歴が消え、ログイン案内に切り替わること、トップへ戻ると未ログイン用入口になることを確認。顧客ポータルの実際のログアウトボタンも確認。匿名問い合わせの氏名・メール欄が初期化され、戻るボタンがログイン画面へ向かうことを確認。

実際のFirebaseへのログイン、実メール送信、実予約の変更は行っていない。Google認証の検証APIは未定義のためログインフォームに404由来の案内が出るが、Googleログインは今回の検証対象外。開発サーバーの初回コンパイル時間を含むため、本番速度の秒数は評価していない。トップに戻る際のお客様情報のAPI取得待ちは認証待ちと区別して維持する。

変更はローカルソースに反映し、本番ビルドで検証。本番・クラウドへのデプロイなし。検証用タブ・API／Nextサーバーを終了し、画面サイズ指定を解除。既存のlocalhost:3000と配送ワーカーは操作していない。
