# アカウント操作の子画面分離

実施日: 2026-10-29。メールアドレス変更・お客様情報と設定・アカウント削除をそれぞれ別の子画面にする依頼。

## 変更

- トップのメール変更・アカウント削除ボタンを専用表示状態emailChange／accountDeletionへの画面遷移に変更し、トップ内の展開フォームを除去。
- 既存のsettings画面からアカウント操作欄と展開フォームを除去。プロフィール、ログイン方法、追加連絡先に集中させた。
- 新しい画面は720pxの共通本文幅とCustomerPageActionsを使用。戻るは下部に集約し、お手続きトップへ戻る。ポータル内の表示切り替えなのでページ再読み込み・認証状態の再初期化なし。
- メール変更フォームにReact Hook Form／Zodで形式・確認一致の検証と項目別エラーを追加。送信中は入力・送信・戻るを無効化し、成功後は入力をクリア。失敗時は入力を保持する。Google本人確認、Firebaseの確認メール送信・再ログイン要件は維持する。
- メール確認リンクの戻り先と旧リンクの結果表示をメール変更子画面へ統一。完了時のAPIは既存のものを維持し、取得失敗はエラーとして表示する。
- 削除画面は対象メールアドレス・注意・パスワード入力またはGoogle本人確認を表示。既存の取り消し不可の最終確認、再認証、本人のAPI、未完了予約等の削除禁止条件は維持。削除完了後はログアウトしてトップへ戻る。
- 入力済みで戻る場合は共通の破棄確認を使用。新画面はUIDをキーにし、アカウント変更時に入力を引き継がない。未ログインの直接アクセスはログイン案内を表示する。

URLは /?customerMode=emailChange、/?customerMode=settings、/?customerMode=accountDeletion。API・DBスキーマ・メール配送・認可ルールは変更していない。

- npm run build: 最終コードで成功。既存のHook依存警告2件（admin-app.tsx、email-template-management.tsx）あり。
- 実際のNext.js App Router、実コンポーネント、モックFirebase、架空データ・一時PGlite DBの隔離環境でPC1280px・スマートフォン390pxを確認。
- トップから3画面へ移動し、下部の戻る操作からトップへ復帰。文書識別子を保持し、認証監視は1回、通常の往復で認証確認・未ログイン画面の表示回数は0回。
- メール変更は必須・不一致の項目別エラー、モック送信中の入力・送信・戻る無効化、送信失敗の案内と入力保持、モック成功後の入力初期化と案内を確認。入力途中で戻ると共通の破棄確認を表示し、入力継続も選択可能。

- 削除画面は対象メール・注意・パスワード・下部操作を表示。空のパスワードでは削除操作が無効。架空の文字列を入力して戻ると破棄確認を表示し、破棄してトップへ復帰。実際の削除送信は実行していない。最終確認と再認証・既存API呼び出しの維持はソースでも確認。
