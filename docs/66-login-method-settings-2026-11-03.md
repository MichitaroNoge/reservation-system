# ログイン方法の設定の改善

実施日: 2026-11-03。利用者が比較・修正案を採用したことに基づく確定仕様。31・32の該当する旧本人確認方式に優先する。

## 画面と本人確認

- customer-login-methods.tsxへ設定UIを分離し、パスワードとGoogle連携を独立した操作欄にした。変更用・連携用・解除用の現在パスワード入力は別のフォームで保持し、共用しない。
- 設定済みパスワード変更はGoogle連携の有無を問わず毎回現在のパスワードでFirebase再認証。パスワード未設定はGoogle再認証で初回設定する。新しいパスワードの8〜128文字・確認一致は維持。再設定メールの入口を追加した。
- Google追加連携の開始直前に最新のログイン方法と、パスワード再入力を省略できるかをサーバーへ問い合わせる。直近5分のパスワード認証があればGoogle選択へ進み、なければ子画面内でパスワード確認後に進む。途中で認証期限が切れた場合はパスワード確認へ戻る。キャンセル・通信失敗・二重操作に対応する。
- Google解除は対象アドレス・解除後のログイン方法・現在のパスワードを子画面に表示し、確認後にパスワード再認証して実行。Google認証は呼び出さない。未設定パスワードでは解除を禁止する。
- 設定入力中の閉じる／トップへ戻るは破棄確認。処理中は設定操作とトップへ戻るを無効にする。操作後のパスワードは消去し、他のアカウントへ操作を継続しない。連携・パスワード変更・解除後の通知と、変更・解除後の全セッション失効／再ログインを維持。

## APIと保護

- GET /api/accounts/me/login-methodsへcanLinkWithoutPasswordを追加。サーバーでパスワード認証の由来とauth_timeの5分制限を判定する。非公開／no-store応答を維持する。
- POSTはoperationをchange-password／set-passwordに分け、トランザクション内で最新のユーザーのパスワード設定状態と一致することを確認。変更はパスワード由来の直近認証、初回設定は連携済みGoogle由来の直近認証を要求する。
- DELETEはパスワード由来の直近認証を要求。Googleだけの認証で既存パスワード変更・解除する要求や、初回設定を偽る要求を拒否する。
- Google連携のチャレンジと確定APIの既存パスワード認証条件を共有関数へ統一。UID・Origin・nonce・署名・単回利用・Google sub・元のGoogle認証時刻・セッション世代・失効・無効ユーザー・管理者制限は維持。
- UIは変更／解除の操作ごとに現在パスワードを入力して再認証する。APIはそのFirebase署名付きトークンの認証手段と直近5分を検証する。現在パスワードはアプリAPIやDBへ渡さない。5分は一般規格の値ではなく、このアプリの既存基準を維持したもの。
- メール変更・アカウント削除は今回の本人確認方式の変更対象外。DBスキーマ・予約データ・プロフィールの自動連携には変更なし。

- 実際のNext.js画面、架空データ・一時PGlite、モックFirebase／Googleを用いた隔離環境でPC1280pxとスマートフォン390pxを確認。UI上の成功応答は検証用で、実ユーザーの認証情報は変更しない。
- Google連携済みでもパスワード変更には現在パスワードが必須。未入力では本人確認を呼ばず、誤ったパスワードではエラーと新パスワード入力を保持する。正しい検証用入力で変更が完了しログアウト。Google認証の呼び出し0回・パスワード確認1回を計測。
- 解除子画面は対象Googleメールと現在パスワード・確認ボタンを表示。空欄では実行せず、パスワードで完了するとログアウト。Google認証の呼び出し0回を確認。PC・390pxともボタンが操作でき、ページ全体の横はみ出しなし。
- 直近パスワード認証ありのGoogle追加はパスワード再入力欄0件でGoogle選択へ進み、モック連携完了。パスワード確認0回・Google認証1回を計測。時間経過時は独立したパスワード子画面を表示し、確認後にGoogle選択へ進む。取得時点では有効でもチャレンジ時点で期限切れの場合は、パスワード確認へ戻ることを確認。
- Googleのみは現在パスワード欄なし・「パスワードを設定」を表示し、解除は無効。初回設定はGoogle本人確認へ進み、モック完了後ログアウト。パスワード確認0回・Google認証1回を計測。
- 取得失敗時はエラーと再読み込み操作を表示し、トップへの戻りが可能。入力済みで設定を閉じると破棄確認を表示し、「入力を続ける」で保持。トップへ戻るときも共通の破棄確認を表示。処理中は関連フォーム・設定の開閉・連携解除・共通の戻る操作が無効。
- 初回の検証用期限切れ応答はStrict Modeの二重チャレンジで2回目だけ成功してしまう設定だったため、検証側だけを修正し、パスワード再認証まで期限切れを維持する条件で再確認。製品側の判定変更はしていない。入力操作はReactへの反映を確認できるキーボード操作で実施。
