# お客様の予約確認画面の改善

実施日: 2026-11-03。担当店舗・確認連絡の非表示、人数・メニューの強調、予約時の入力内容を確認できるようにする依頼に基づく確定仕様。

追記: 同日の追加依頼により、文字サイズ・余白・区分表示は[69. 予約確認の表示密度の改善](69-customer-reservation-density-2026-11-03.md)の仕様へ更新。以下は初回変更時の記録。

## 表示内容

- 予約一覧カードから担当店舗・確認連絡の状況を除去。予約状況・日時・予約ID・利用者区分は維持する。
- 人数は24px、メニューは18pxの太字で背景と区切りを付けて表示。PCでは隣接、狭い幅では縦並び。複数メニュー・長い名前は全文を折り返す。
- 各予約に「予約内容の詳細」を設置。取得済みの予約を読み取り専用で表示し、開く際の追加通信は発生しない。
- 詳細は利用日時・人数・メニュー、予約時の氏名／会社支店名・電話・メール・住所、支払条件・備考を表示する。団体では予約担当者、当日責任者・携帯番号、団体名・ふりがな・種別・その他、T/C・D/Gも表示。保存済みのポリシー同意履歴は既存の表示部品を使用し、旧同意情報がある場合も表示する。
- 任意項目の空欄は「未入力」と表示し、現在のプロフィールから補完しない。メニューが空なら「メニュー未確定」。備考の改行を維持。過去の連絡先・メニューのスナップショットを使う。
- Radix Dialogと共有Buttonを使用。最大720px、スクロールする本文、固定のタイトル・閉じる操作、Escapeとフォーカス復帰を備える。下部のトップへの戻る操作と重ならない。
- 新しい部分はTailwindと意味別トークンを使用し、不要になった予約カードの旧CSSを削除。管理画面の店舗割当・確認連絡、予約API・DB・本人の閲覧条件・申請判定は変更しない。

## 検証

- npm test: 177件成功。
- npm run build: 成功。既存のHook依存警告2件（admin-app.tsx、email-template-management.tsx）は継続。
- モック認証と架空データ・一時PGliteを使用する実際のNext.js画面で、一般予約・団体予約・メニュー未確定の仮予約を確認。
- 担当店舗と確認連絡済みの値を持つ予約でも、一覧と詳細にその項目・店舗名は出ないことを確認。
- 一般予約の氏名・連絡先・住所・カード払い・複数行の備考、団体予約の全項目・請求書払い・その他種別・2名のT/Cと1名のD/Gが保存値どおり表示される。人数は45名のままで内訳を加算しない。未入力の住所・備考と未確定メニューも確認。
- PC1280pxとスマートフォン390pxで、人数24px・メニュー18px、ページと詳細に横はみ出しなし。長いメニュー名・備考を確認し、スマートフォンで詳細末尾までスクロールでき、閉じる操作が常に表示される。Escapeで元の予約のボタンにフォーカスが戻る。
- 問い合わせ履歴と新規問い合わせは同じ行のまま。履歴のある予約のみ有効で、その他は無効。仮予約の本予約への変更ボタンと申請中の無効化も維持。
- 実ユーザー・実予約・クラウドDBの変更や実メール送信、本番デプロイは行っていない。
