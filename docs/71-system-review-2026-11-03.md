# システム全体レビューと改善

実施日: 2026-11-03。現在のシステムをレビューし、問題が見つかった場合は改善する依頼に基づく。既存の未コミット変更は保持し、本番操作や既存DBの初期化は行わない。

## レビュー範囲

| 対象 | 確認した内容 |
| --- | --- |
| 予約・変更・キャンセル | API入力検証、本人の予約へのアクセス、予約単位のトランザクション、更新の競合、受付期限、キャンセル料確認 |
| 管理機能 | 管理者権限、店舗割当・人数、承認、一覧取得・CSV、画面の一覧／詳細 |
| 問い合わせ | 匿名送信の証明、本人の履歴、回答保存とメール配送の分離、再試行・リース・公開状態 |
| 認証・アカウント | トークンの失効確認、Google／パスワードの操作別本人確認、メール変更・削除、追加連絡先の確認 |
| 外部連携・運用 | メールの送信キー・スナップショット・再試行期限、定期処理からの呼出し、カレンダー同期のキュー、検証環境の隔離 |

ソース・確定仕様・既存テストの照合と、一時PGlite／モック配送／Authエミュレーターでの検証を行った。実Google OAuth画面・実メール配送・本番の負荷や複数PostgreSQL接続での競合を再現したレビューではない。

## 検出して修正した問題

| No. | 優先度 | 問題・再現と修正 |
| --- | --- | --- |
| 1 | P1 | 受付メールはキュー側だけで再送期限を確認しており、定期処理から直接サービスを呼ぶ経路では23時間超の結果不明メールを再送できた。保存済みの初回配送日時をサービス本体で確認し、期限超過・不正な日時では送信せず自動再送を停止する。既存の本文・宛先・キーを維持し、23時間ちょうどの再試行は維持。 |
| 2 | P2 | 受付メール自体の送信記録は保存できたが、予約側の更新に失敗した場合、後日の復旧が本来の送信日時を復旧日時で上書きしていた。送信済み監査記録の日時を保持して予約側を復旧し、メールは再送しない。 |
| 3 | P2 | 確認メールのバッチに渡したtimeoutMsが個別送信へ渡らず、指定しても20秒の既定待機になっていた。バッチから個別サービスへ引き継ぎ、送信結果不明時は確認連絡済みにしない。 |
| 4 | P2 | 追加連絡先は、確認済みでも元の期限経過後に同じリンクを開くと無効扱いになる一方、無効化／削除中のアカウントのリンクを確認できた。アカウント単位のロック内で所有者・有効状態・削除状態を確認し、未確認時だけ期限を判定。確認済みなら元の確認日時を保持する。リダイレクトを設定画面にし、no-store／no-referrerを付け、Next.jsの開発アクセスログとエラーログに生のトークンやDBエラーを出さない。 |
| 5 | P2 | 確認リンクの結果を設定画面へ移した後、Strict Modeによる初期化の再実行が初期モードを上書きし、トップへ戻していた。初期モードは同じ値を重複適用しない。併せて、成功表示がAlertの既定のエラー色を引き継いでいたため、成功トークンの色とrole=statusを指定。失敗はrole=alertを維持。 |

予約・ログイン方法の業務ルール、主要な認証／認可方式、DBスキーマ・マイグレーション、依存パッケージは変更していない。

## テストと画面確認

- 修正前に受付メールの期限超過・送信日時の上書き・タイムアウト無視を通常テストで再現。確認済み期限切れリンクの誤判定も実SQLのAPIテストで再現した。
- 通常テストへ4件、DBテストへ1件を追加。DBの1件では有効・期限切れ・期限ちょうど・確認済み期限切れ・無効アカウント・確認済み無効アカウント・削除中・不正トークン、元の確認日時・応答ヘッダー・戻り先を照合する。
- 統合検証では通常183件成功、DBは80件中69件成功・実PostgreSQL専用11件skip・失敗0件。Authエミュレーターの契約テスト1件成功。DBの初期化を伴う実PostgreSQL検証は実行しない。
- 実際のNext.jsのStrict Modeで、確認成功の表示がトップへ戻される問題を観測し、修正後は設定画面・成功表示を保持。旧形式のhomeからの確認結果URLも確認した。
- 架空ユーザー・一時DB・モックFirebaseのみの画面で、顧客の確認結果・設定→トップ→予約確認、管理者のダッシュボード→予約一覧→予約詳細をPC1280px・スマートフォン390pxで確認。管理一覧は768pxでも横はみ出しなし。失敗リンクも設定画面にエラーを表示する。
- 成功メッセージは緑色・role=status、エラーはrole=alert。スマートフォンの成功／エラー表示でページの横はみ出しなし。管理者画面の送信・保存・削除・承認の操作は画面確認では行っていない。
- 画面検証サーバーへ確認リンクのAPIを接続していなかった初回は検証用404となったため、検証用ルートを追加して再実行した。製品側の404修正としては扱っていない。

画面変更後の最終コードで型生成・型チェック・Lint（警告0件）・通常テスト183件・検証ビルドも再実行し、すべて成功。先行する統合実行も終了コード0。新しい確認リンクの全ケースと設定画面への戻り先はDB全体検証に含めて成功している。
