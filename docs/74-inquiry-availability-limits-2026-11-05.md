# 空き状況問い合わせの人数上限・過去日チェック（2026-11-05）

## 採用仕様

- 人数は1〜999名の整数。ブラウザーの入力上限と共通Zodスキーマの上限をそろえる。
- 新規受付の食事日は、送信時点の日本時間で本日以降。同日の過ぎた開始時間は禁止しない。
- 日付選択の最小日を本日にする。手入力の過去日には、食事日欄で「食事日は本日以降を指定してください。」と表示する。
- 画面を開いたまま日付が変わった場合も、日付境界・画面復帰で最小日を更新し、送信時に再検証する。エラーでも入力を保持する。
- サーバーの新規作成処理でも同条件を検証し、未ログイン・ログイン済みの両方に適用する。

## 実装

- `lib/inquiries/availability.ts`に人数上限、日本時間の日付取得、過去日のエラーメッセージを集約した。構造の検証と新規受付時の日付判定は分け、過去の履歴を引き続き扱えるようにした。
- `components/inquiries/contact-form.tsx`でカレンダーの最小日と人数の最大値を指定。React Hook FormとZodで送信時に現在日を検証し、項目別エラーを表示する。
- `app/reservations/api-client.ts`でAPIの項目別エラーを保持し、サーバーが検出した日付・人数のエラーも入力欄に反映する。
- `lib/inquiries/repository.ts`の新規受付トランザクションで日付を再確認する。既存の送信キー照合を先に行うため、受付直後に日付が変わり応答だけ失われた場合も、再試行で元の結果を取得できる。新しいキーによる過去日の受付は拒否する。
- 既存の認証・認可、送信頻度制限、メールキューを維持した。DB変更・依存パッケージ追加はない。
