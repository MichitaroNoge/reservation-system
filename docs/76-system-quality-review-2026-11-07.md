後続の[修正内容の再レビュー](77-quality-fix-re-review-2026-11-07.md)で、HTTP状態付きのインフラ例外による秘匿化迂回、不正な状態コードの受理、保存済み無効店舗の選択表示の不足を確認して追加修正した。本書は初回レビュー時の記録として保持する。

## 1. 対象と確認方法

AGENTS.md、標準仕様、認証・DB・予約・変更承認・店舗割当・通知・問い合わせ・顧客画面・検証の関連仕様を照合した。提案部分は追加要件として扱っていない。開始時の作業ツリーは変更なし。

| 範囲 | 確認方法 |
| --- | --- |
| 顧客・管理画面 | 予約入力、本人予約、変更・キャンセル、設定、店舗割当、フォーム・エラー処理の静的確認。実コンポーネントを隔離プレビューで操作 |
| 認証・認可 | Firebaseトークン失効確認、管理者判定、UIDによる所有権、追加連絡先、メール変更・削除、Google本人確認をコードと既存の拒否テストで確認 |
| API・セキュリティ | 入力上限、SQLパラメーター化、HTMLエスケープ、匿名証明・Origin、個人情報のエラー漏洩、依存監査 |
| DB・業務処理 | 実SQLマイグレーション・Repository・一意制約・トランザクション・ロールバック・古い版の拒否を一時PGliteで確認 |

## 2. 発見・修正した問題

| 問題 | 重大度・原因・影響 | 修正と根拠 |
| --- | --- | --- |
| 承認通知の再送期限の抜け | P1。外部送信後のDB確定失敗で試行回数が0へ戻ると、23時間超の同じプロバイダーキーを再送でき、重複配送の危険がある | 通常テストで0回のまま期限超過で送信されることを再現。保存済み本文の準備日時を判定基準にし、回数による条件を除去。新しい本文の日時は初回の準備時刻にし、長期間キューに滞留した未送信通知の最初の送信は維持する。23時間ちょうどは許可。SQLロールバックの統合テストも追加 |
| 内部エラー詳細の公開 | P1。Data Connectの例外・response.errors、汎用のnot found/already exists例外の本文をそのまま返し、個人情報や内部操作名を含められる。Data Connect等の例外全体もログへ出力していた | 架空のメールアドレス・秘密値を含む例外で再現。HTTP分類を保持し、安全な固定文言へ変更。予期しない例外・認証設定エラーは構造化イベントとして記録。PostgreSQLの制約別応答を維持 |
| 無効店舗への新規割当 | P2。画面は有効店舗を選ばせるが、Drizzleの保存処理はactiveを確認せず、停止した店舗をAPIで新規選択できた | APIが修正前は200を返すことを再現し、現在無効な店舗の新規選択は400で拒否。元の割当・確認日時をトランザクションで保持。有効化後の保存と、既に保存済みの無効店舗の保持・再保存は許可 |
| 店舗割当で団体名を検索できない | P2。仕様には団体名検索があるが、IDと顧客名しか検索していなかった | 団体名を対象に追加。共通検索欄には任意のラベルを渡せるようにし、この画面で団体名を明記。他の検索条件は維持。実画面で団体名のみの検索が1件へ絞られることを確認 |
| 追加連絡先を確認なしで削除 | P2。削除ボタンから直ちにDELETEを実行し、AGENTS.mdの破壊的操作の確認要件を満たさない | 既存のアカウント削除等と同じブラウザー確認を追加。キャンセル時はAPIを呼ばない。実アカウントでの削除操作は未実施 |
| 予約手順で検証済み日時が予約本体へ渡らないケース | P2。フォーム内の日時が検証を通っても、次の手順へ進む処理はその値を捨ててonNextだけを呼び、親の値との同期に依存していた | ブラウザーのフォーム操作で次画面が「日時未入力」になり、戻ると日時が空になる状態を観測。日付・時刻も人数と同じControllerで同期し、次へ進む前に検証済みの3項目を必ず親へ渡す。修正後は要約と戻ったフォームの日時・人数・メニューを保持。ネイティブ入力と連続した自動入力のイベント差があるため、全実ブラウザーで発生するとは断定しない |
| 配列の上限判定より先に全要素を検証 | P2。Zod 3の.max()は要素解析後に判定し、設定・CSVの上限超過入力で大量のエラーを生成できる | 元のスキーマが上限を超えても要素へアクセスすることを再現。共通boundedArrayで要素へ触れる前に致命的な上限エラー1件で停止。上限ちょうどの正常入力を維持。大規模なメモリー枯渇攻撃の成功は実証していない |
| 依存パッケージの既知脆弱性 | 監査でNext.jsにCritical/High、RE2JS等にHighが報告された。攻撃条件は機能・環境に依存し、このアプリへの攻撃成功は未確認 | Next.js・@next/env・eslint-config-nextを15.5.27から15.5.29へ更新。間接依存とFirebase CLIは既存の制約内で更新。npm audit fixの一括適用は避け、メジャー変更・ダウングレードを強制しない |

Next.jsの根拠: [開発元のセキュリティ告知](https://github.com/vercel/next.js/security/advisories/GHSA-2464-fhr4-w9xw)、[Server Actionsの告知](https://github.com/vercel/next.js/security/advisories/GHSA-p3m5-59mp-jv5r)。前者はglibc Linuxの画像最適化が条件。ソース上はnext/imageやServer Actionsを使っていないため、監査の重大度と、このシステムで攻撃条件を確認できたかを区別する。

## 5. 未修正・未確認事項と残存リスク

- 最終npm auditは全依存で23件（High 1、Moderate 22）、本番用依存で5件（High 1、Moderate 4）。件数は依存関係の連鎖を含むパッケージ警告で、別々の攻撃実証件数ではない。監査は警告があるため終了コード1であり、成功扱いにしない。
