# 管理画面の操作統一

2026-11-11。管理者向け全機能の横断調査後に提示した改善案について、ユーザーの「提案してくれた内容ですべて修正してください」に基づく採用仕様。

## 共通の操作

- 一覧の行選択と明示的な詳細・編集ボタンは同じ処理を呼ぶ。文字選択では開かず、行内ボタンは伝播を止める。承認系の一覧は「内容を確認」に集約する。
- 承認・却下・キャンセル・来店記録・手動状態変更・連絡記録・メール送信／再試行・無効化／有効化・外部連携の変更は、対象・影響・最終操作名を示す共通確認から実行する。通常のフォーム保存、検索、表示切替、CSV出力は直接実行する。
- 主要操作は下部の右側に置く。閲覧は「閉じる」、通常編集は「キャンセル／保存する」、確定前は「戻る／具体的な実行名」。問い合わせの送信本文プレビュー、送信結果の選択と同意、下書きの3択は既存の専用内容を維持する。
- 確定処理は共通ゲートで直列化し、失敗・明示的な未完了を成功として扱わない。失敗時は確認を閉じず、再試行可能なエラーを表示する。確認メールの一括処理は成功済み対象を除外して失敗分だけ再試行する。
- 保存に成功してから編集を終了する。未保存の閉じる、Escape、外側クリック、管理画面移動、ログアウトは入力破棄を確認する。問い合わせの下書き保持は同一ログイン中という既存範囲を維持する。
- フォームは項目ラベル・必須・項目別エラーを関連付ける。管理者の予約入力は過去日を表示・修正できる既存仕様を維持し、顧客の予約受付締切を流用しない。T/Cは予約人数の内数を維持する。
- 保存とメール配送の結果を混同せず、通知の色は明示的な成功・エラー・案内で選ぶ。読込中・取得失敗は0件と区別する。

## 全画面の対応

| 対象 | 対応・維持する固有操作 |
| --- | --- |
| ダッシュボード | タスクから専用一覧への導線、要対応／取得中／エラーの区別を維持 |
| 予約一覧 | 検索・ソート・CSV・ページ送りを維持。登録と詳細編集は共通フォーム |
| 予約承認 | 一覧は内容確認。受入状況の再取得・承認不可条件を維持し、承認も必ず確認 |
| 本予約変更承認 | 予約承認と同じ導線。却下時に仮予約へ戻る既存処理を維持 |
| 予約変更承認 | 一覧から変更比較を開き、比較画面の承認・却下から確認して確定 |
| キャンセル承認 | 一覧から詳細を開き、確認後に確定。失敗時は詳細を閉じない |
| 確認連絡 | 個別・一括送信、手動記録、未連絡への差戻しを区別して確認 |
| 店舗割当 | 全有効店舗の人数入力を維持。未保存破棄と全解除を共通確認 |
| 予約リマインド | 対象条件と予約詳細への導線を維持 |
| メニューリマインド | 対象条件と予約詳細への導線を維持 |
| 予約カレンダー | 月間・週間・店舗別、日別一覧と共通予約詳細を維持 |
| 問い合わせ | 下書き・回答確認・保存と配送の区別を維持。失敗時は確認を保持。再試行も確認 |
| マスタ・設定 | マスタ、メール、外部連携を含む入口名へ統一 |
| 顧客管理 | 中央編集と項目別エラー。無効化・有効化の確認。削除済みの復活禁止を維持 |
| 店舗管理 | 共通中央編集。無効化と履歴保持を明示 |
| メニュー管理 | 店舗と共通中央編集。既存金額・履歴を維持 |
| メールテンプレート | 中央編集、プレビュー、保存成功で終了。送信停止は影響を確認 |
| 問い合わせ回答テンプレート | 中央編集・複製・有効状態を維持。未保存破棄を確認 |
| 予約通知メール | 履歴確認の同意を共通確認へ移行。送信と送信済み記録を区別 |
| その他設定 | 未保存／保存済みを表示。期間削除の確認と保存での反映を明示 |
| Googleカレンダー連携 | 作成・停止・再開・同期・復旧・解除の影響を共通確認。OAuthと既存の復旧制約を維持 |

ログインの認証処理と権限判定、状態遷移、抽出条件、取得単位、更新間隔、API・DB・実メール・外部カレンダーの仕様は変更しない。

## 検証

変更区分は広範囲のUI操作・入力検証。検証仕様に従い型・Lint・通常テスト・PGlite・検証ビルド・認証契約を実行する。新規テストは多重実行防止、失敗からの再試行、一括処理の部分失敗、予約入力の項目別検証・人数境界・団体入力・メタデータ保持を対象とする。

PC1280px・モバイル390px・タブレット768pxの実表示・操作確認は必要。架空データと外部接続を遮断した隔離画面を準備したが、組み込みブラウザーはローカル接続がタイムアウト、Windows Computer Useは現在のブラウザーURLを確認できず停止したため未実施。実予約の更新・実メール・実Googleへの操作はしていない。静的検証の成功を画面確認の成功として扱わない。

| チェック | 最終結果 |
| --- | --- |
| `npm run typecheck` | 成功 |
| `npm run lint` | 成功・警告なし |
| `npm test` | 218件成功・失敗なし |
| `npm run test:db` | PGliteで86件成功、PostgreSQL専用13件skip・失敗なし |
| `npm run build:check` | 成功・検証用`.next-check`に出力 |
| `npm run test:auth` | demoプロジェクトのAuthエミュレーターで1件成功 |
| `git diff --check` | 成功 |

`verify`の構成要素を個別実行して全項目を満たしたため、同じ統合コマンドを重ねて実行していない。認証エミュレーターはサンドボックス内でローカルポート4400の起動がタイムアウトし、検証ビルドは生成先ディレクトリ作成がEPERMとなったため、それぞれ同じ隔離設定のまま制限外で再実行して成功した。実PostgreSQLを初期化する任意テストは、DB・マイグレーションを変更していないため実施していない。

既存のソース構造・旧ラベルを前提としたUI回帰テストは、新しい導線・表示名と実際の承認判定の検証へ更新した。テストの無効化はしていない。既存の未コミット変更を保持し、コミット・Push・デプロイは実施していない。

最終の設定入口名の案内文調整は文言のみの変更として型・Lintを再実行した。動作を変えないため、成功済みの通常テスト・DB・認証・ビルドはこの文言変更だけでは再実行していない。
