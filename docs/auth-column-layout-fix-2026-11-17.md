# ログインボタンのカラム越え修正（2026-11-17）

## 発見した問題と原因

利用者の画像と同じ825px幅で再現した。ログイン画面のメール認証フォームは2列表示時に326px、その内側は左右24pxの余白を除いて278pxだった。一方、パスワード再設定リンク・12pxの間隔・最小幅144pxのログインボタンは合計311.64pxを必要とした。

操作行は画面幅640px以上で横並びになるが、折り返しを許していなかった。このため、ボタンは入力欄の右端から33.64px、左カラムの区切り線から約9.64px外へ出ていた。予約途中のログインにも同じ共通フォームが使われ、25.64pxのはみ出しがあった。

前回の表示監査はページ全体の横はみ出しと文字のクリップを中心に判定しており、ページ内の隣のカラムへ出るボタンを検出できなかった。スクリーンショットの確認でもこの箇所を見落とした。前回の「横はみ出し0件」は、フォーム内部の配置まで保証する結果ではなかった。

## 修正

製品コードの追加変更は、共通の`CustomerAccountAccessPanel`の操作行2箇所。

- ログインボタンの`sm:min-w-36`を削除し、文字と余白に応じた自然な幅にする。
- 横並び時も折り返しを許可し、ボタンを`sm:ml-auto`でフォーム内の右端にそろえる。
- モバイルでの主要操作の全幅表示・高さ・表示順、ログイン処理、入力検証、パスワード再設定の動作は維持する。

825px幅の修正後はボタン右端387.5pxとフォーム内側の右端387.5pxが一致した。通常ログインボタンは自然な幅88pxとなり、入力欄の外へ出ない。Noto Sans JPは維持している。

## 制約と作業範囲

- Chromeでの画面幅・状態の検証で、実機Safari・Firefoxや実Google OAuthは未検証。
- Googleウィジェットの外観・認証の完全な再現ではなく、実際のコンポーネントが指定した幅で隣のカラムを占める条件を検証した。
- API、業務ルール、DB、認証実装は変更していないため、DBテスト・認証エミュレーターは今回の対象外。
- 現在の`codex/performance-investigation`で作業し、既存の未コミット変更を保持した。mainへのマージ・デプロイは行っていない。

検証後、今回起動した隔離API・Next.jsサーバーは停止した。
