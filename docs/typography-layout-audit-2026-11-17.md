# フォント・レイアウトの全画面調査（2026-11-17）

同日追補: ログインボタンのカラム越えを見落としていたため再調査・修正した。ページ全体のはみ出しに加えてフォーム内の境界も検査するようにした。最新の原因・修正・確認結果は[ログインボタンの修正記録](auth-column-layout-fix-2026-11-17.md)を参照。

## 対象と安全性

現在のworktree、`codex/performance-investigation`で実施。既存の予約時間・性能改善の未コミット変更を保持し、mainへのマージ、コミット、push、デプロイは行っていない。

対象はログイン前・後の管理／顧客画面と各ダイアログ。Next.jsの実際の画面を使用し、既存の`performanceFixture`／PGliteと模擬Firebase認証を再利用した。実DB、実アカウント、実メール・カレンダーには接続しない。視覚検証用の長い顧客名・住所・メニュー名・店舗名・問い合わせ本文・URL・各予約状態を一時DBに追加した。ワーカーは起動しない。

## 発見と修正

| 問題 | 確認した原因・証拠 | 最終修正 |
| --- | --- | --- |
| 端末ごとに書体・太さが変わる | 修正前のフォント通信0件。Chromeの描画フォントはローカルのNoto Sans JP（`isCustomFont: false`）。600指定の見出しでもPostScript名はBoldだった | `@fontsource-variable/noto-sans-jp@5.3.1`を固定追加。同一サイトから可変WOFF2を配信。400／500／600をフォントの実ウェイトで描画 |
| 強調文字が重い | 旧CSSに700／800が34箇所、`strong`等にブラウザー標準の700、ロゴに`font-bold` | 旧指定と見出し・strongを600、本文400、ラベル500に整理。色や文字サイズは維持 |
| 疑似太字の可能性 | 事前ログだけでは疑似太字の発生そのものは断定できない。端末フォントと選択ウェイトの差は確認できる | `font-synthesis-weight: none`。可変フォントの100〜900対応と、実描画のMedium／SemiBold、`isCustomFont: true`を確認 |
| ラベルの窮屈な行間 | 共通Labelは14px文字に行間14px（`leading-none`） | 行間20pxへ変更。本文は1.55→1.6。必須表示は500・縮小しない設定にし、ラベル行も折り返せる |
| 長い操作名が固定高に収まらない | 共通Buttonは折り返し禁止・高さ42／44px固定 | 通常操作は折り返しを許可し、最小高を維持して必要な分だけ伸びる。アイコンは縮めない |
| 表内操作が縦に折れる | 最初のButton調整を表に適用すると「内容を確認」「詳細」「編集」が1〜2文字ずつ折れることを目視確認 | 表内のButtonは1行表示に限定。既存の内部横スクロールと固定した主要操作列を維持 |
| 設定ツールバーの説明が細くなる | 問い合わせ回答テンプレートの説明が、件数・更新・新規登録に押されて縦長になっていた | 共通ListToolbarの説明文を狭幅では別行に置く。件数は縮小しない |
| 長い管理画面タイトル | 固定高64pxのヘッダーで、長いタイトルと日付が同じ行を取り合う | 共通ヘッダーを最小高・折り返し可能に変更。スマートフォンではタイトルと日付を別行に配置 |

配信用フォントの内部ファミリー名は`Noto Sans JP Variable`で、別のデザインの書体ではない。共通トークンは`"Noto Sans JP Variable", "Noto Sans JP", sans-serif`。`font-display: swap`とUnicode範囲による分割を利用し、フォント待ちで本文を隠さず、全ファイルの一括プリロードはしない。ライセンスは`public/fonts/noto-sans-jp-OFL.txt`に同梱した。

## 反復確認

1. 変更前にChromeの実描画フォント、計算済みウェイト・文字サイズ・行間、フォント要求、3画面幅の予約フォームを記録。
2. フォント配信・共通ウェイト・ラベル・Buttonを調整し、画面監査スクリプトで撮影。
3. 自動検出でページのはみ出しがなくても、目視で表内操作の縦折れ、ツールバー説明文の圧縮、長いタイトルを発見。共通側で修正して再確認。
4. 本番ビルドで基本68画面・状態を撮影し、カレンダーの別表示、処理済み履歴、予約編集、団体予約、各申請、完了画面を追加確認。
5. 履歴一覧の行全体では詳細へ遷移しないため、詳細リンクを明示して対象画面を再確認。承認操作で一時DBに実際の履歴を保存し、空ではない履歴一覧・処理詳細も追加確認。

途中で監査スクリプトの実行文脈・タブのrole・多重ダイアログの閉じ方・読み込み完了の待機を修正した。失敗した試行を確認済み件数に含めない。開発中にクライアント初期化が停止した試行は完了扱いにせず、開発サーバーを終了し、本番ビルドの新規ブラウザーコンテキストで最終確認した。

## 再現方法

```powershell
npm run build:check
# 端末1: 実設定を除去した既存の隔離環境。メールワーカーは起動しない。
npm run perf -- server production 1000 --visual
# 端末2
node --import tsx scripts/visual-audit.ts typography
node --import tsx scripts/visual-audit.ts typography-extra --extra
```

`--visual`は追加の架空データ・テスト認証をPGliteにだけ用意する。通常の性能計測時は指定しない。`--extra`には一時DB内での登録・承認・キャンセルが含まれる。特定の追加確認だけを行う場合は、例として`--extra --only=member-inquiry-detail`を指定できる。Chromeの独立した一時プロファイルを使用し、利用者のブラウザーは操作しない。

元の画像・生ログはローカルの`.tmp/visual-audit/`に保持。最終確認の対象は`final`、`final-extra`、`final-inquiry`、`final-history`で、途中の`round*`は調査用記録。検証データJSONには最終として採用した保存先を明記した。

## 制約・未検証

- 実機のiOS Safari・Android Chrome・Firefoxでの描画、OS固有の文字レンダリング、拡大表示は未検証。今回の結果はWindows Chromeでの3画面幅の確認。
- 実Google OAuthの同意画面、Googleだけで登録したアカウントの初回パスワード設定・Google再認証、実メールの確認リンク／再設定／変更完了、アカウント削除の完了は未検証。実サービスの認証情報・アカウントを使わず、Googleが未設定の場合の案内と関連入力画面を確認した。
- フォントの疑似太字を変更前から確実に再現したとは主張しない。変更後は実ウェイトの自己配信と疑似太字禁止を確認済み。
- 自己配信による追加の転送量がある。全92画面を通して使ったUnicode分割の合計は37ファイル・801,048bytesで、1画面の初回転送量ではない。利用した文字の範囲だけ取得し、以降はブラウザーでキャッシュされる。低速回線でのフォント切り替わり・CLSの定量計測は今後の候補。
- このブランチでの修正であり、別のチェックアウト・本番環境への反映は行っていない。

検証終了後、今回起動したNext.js／隔離API／Storybookを停止し、3310・3311・6006番ポートに残存がないことを確認した。既存の開発環境は停止・変更していない。
